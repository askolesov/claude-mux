claude-mux: how it works

What a terminal really is, what tmux does with one, and how claude-mux connects a browser tab to a running claude.

claude-mux does not use tmux. tmux isn't installed on this Mac, so the Go server does tmux's core job itself: it opens a pseudo-terminal for each claude and keeps it open. There is no tmux session to attach to. You can connect to these sessions only through the web page, which is what the server serves. More in your questions.

1. What is a terminal?

Once a terminal was a physical device: a keyboard and a screen on a serial cable. Programs still talk as if one were there. Today the "device" is a pseudo-terminal (pty): a pair of file descriptors the kernel gives you.

The whole "protocol" between the two ends is a stream of bytes in each direction:

  • Program → screen: text with ANSI/VT100 escape sequences mixed in. ESC[31m means red, ESC[2J clears the screen, ESC[5;10H moves the cursor. Claude Code's whole TUI is drawn this way.
  • Keys → program: plain bytes. Enter is \r, Ctrl+C is \x03, ↑ is ESC[A.
  • One side channel: the window size. The emulator sets it with an ioctl(TIOCSWINSZ) call, and the program gets SIGWINCH and redraws.

So "connecting a terminal" just means holding the master fd: whoever holds it reads the screen bytes and writes the keystrokes.

2. What tmux does with that

tmux puts a long-lived process between your emulator and your programs:

  • The tmux server holds the master side of a pty for every pane. It is a terminal emulator itself: it parses the escape sequences and keeps each pane's screen in memory.
  • A tmux client (what runs when you type tmux attach in iTerm) connects to the server over a Unix socket, by default /private/tmp/tmux-501/default. -L name picks another socket. The server redraws the pane into your real terminal.
  • Detaching closes only the client. The server and its ptys stay up, which is why tmux sessions survive closing the window.

Does tmux have an API?

Yes, two kinds, both over that same socket:

  • Commands: every tmux command can be run from a script. tmux new-session -d -s work claude, tmux send-keys -t work 'hi' Enter, tmux capture-pane -p -t work (read the screen), tmux list-sessions -F '#{session_name} #{pane_pid}', tmux pipe-pane (copy output to a command).
  • Control mode (tmux -C / -CC): a line-based text protocol for programs, which iTerm2 uses for its native tmux integration. The server sends notifications like %output %3 <bytes> and %window-add @2. The client sends commands and gets %begin … %end blocks back.

3. claude-mux, end to end

The Go server plays tmux's role: it holds each pty's master fd. The page plays the client's role, over a WebSocket instead of a Unix socket.

One keystroke, end to end

  1. You press a in the tab. xterm.js fires onData("a").
  2. The page sends {"t":"in","d":"a"} on the WebSocket.
  3. The server writes the byte a to the pty master.
  4. claude reads it from stdin and redraws its prompt line: it writes text plus escape codes to stdout.
  5. The server reads those bytes from the master, appends them to the scrollback, and sends them as a binary frame to every open tab.
  6. xterm.js parses them and paints the grid.

4. Your questions

What tmux session do we use?

None. Each claude is a direct child of the claude-mux process, which holds its pty master fd. The server is the "tmux server", and the page is the only client.

Can I connect to it myself?

Not from iTerm. There's no socket a terminal could attach to, only the web page. Any number of browser tabs can attach to the same session at once, and they all see the same screen.

If I start claude in iTerm, does it appear in the UI?

Yes, under Other terminals, within 5 s: name, AI title, busy/idle, and its last 40 messages, read-only. To move it into the page, quit it there (/exit) and press Take over. That runs claude --resume <id> in a new tab.

What happens if the server stops?

The pty masters close, so every claude gets a hangup and exits, the same as closing a terminal window. The conversations are in the transcripts, so after a restart each tab shows stopped → Resume. Tools that were running mid-turn are lost.

5. The tmux alternative

A tmux backend would give you the two things this design lacks: sessions that outlive the server, and attaching from iTerm.

Now: own ptys

  • No dependencies; one Go binary.
  • Keys, scroll and mouse go straight to claude; nothing in between.
  • A server restart ends the sessions (they can be resumed).
  • No way to attach from a terminal.

With tmux (brew install tmux)

  • Each tab is tmux -L claude-mux new-session -d claude … on a private socket.
  • The page attaches by running tmux attach -t <tab> in a pty, or through control mode.
  • Sessions survive restarts of claude-mux; tmux -L claude-mux attach -t test works from iTerm.
  • A tab opened from iTerm with tmux -L claude-mux new -s x claude would show up as a full tab.
  • Cost: tmux sits in the middle, so scrolling, mouse and some key combos need tmux config.
